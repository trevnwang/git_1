### 4. 原文超长文本块（逐字转写）

#### 4.1 `hv4APbYuL6OXi96OPKf1-78`（聚合规则）

```
把所有相同前缀的仓库聚合成一个名字（称为组件），列新的数据表，比如：
CF325F_ChanganSigProcgBascFct_Design
CF325F_ChanganSigProcgBascFct_Impl
CF325F_ChanganSigProcgBascFct_MIL
CF325F_ChanganSigProcgBascFct_SIL
就可以聚合成同一个组件CF325F，它的整体状态由子仓库状态决定
一个组件通常有四个仓库
```

#### 4.2 `hv4APbYuL6OXi96OPKf1-99`（主界面详细交互规则，逐字转写）

```
1. 菜单栏用来登录认证，配置参数，配置完成后保存为本地json
2. 标题栏显示程序Title，版本，管理的总组件数和仓库数
3. 组件卡片列表显示所有的组件，以及他们子仓库的信息：
3.1 卡片以颜色显示子仓库信息Design Impl MIL SIL等，灰色为MISS，黄色为冲突，红色为超前，绿色为同步，其他颜色为滞后
3.2 卡片本身的颜色由聚合后的组件状态决定，颜色同上
3.3 如组件的子仓库有未提交的change，则子仓库的组件名和对应子仓库信息Design Impl MIL SIL要在右侧加*号示意，比如CF325F*和Design*
3.4 卡片本身需要显示仓库的当前分支，如果四个子仓库当前分支不一致，显示Impl仓库的当前本地分支
3.5 卡片本身需要提供SYNC按钮，点击以后会操作所有子仓库，使用远程分支覆盖本地，如果本地有变更或者超前的分支会提示用户是否强制使用远程最新版覆盖本地。
3.6 卡片本身需要提供CREATE按钮，点击以后要求用户输入需要创建的分支名称，一次性给当前所有子仓库创建同样的分支，创建之前需要先dryrun，看看是不是重名，或者是不是当前最新版。
4 文件树区域的最上方显示仓库名称，并按照3.3规则加*号
5 文件树右侧有选中仓库的基本信息，所有提交历史。滞后超前等，还有远程的build结果是否失败。
6. 下方按钮PULL FETCH CHKOUT COMMIT PUSH都是单个操作，不同时对四个子仓库发起，只对当前选中的仓库执行
7. 最下方状态栏显示软件运行是否正常，以及后台几个进程有没有问题等。
8. 其他功能暂时不表
```
