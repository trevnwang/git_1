# MBD组件全生命周期Git工具

MBD组件全生命周期Git

## 一、HLR 高阶需求文档（High-Level Requirements）

### 1. 产品定位

本软件为 Windows 桌面客户端，面向 Model-Based Design 汽车嵌入式组件开发场景。

核心解决行业痛点：

- 业务以「组件」Component 为单位管理，Git 以 4000+ 独立仓库存储，以下称 Repo（Repository），天然割裂
- 一个 Component = 4 个固定生命周期 Repo（Design / Impl / MIL / SIL），如 Component `CF123A_ShortName` 有四个 Repo：`CF123A_ShortName_Design`、`CF123A_ShortName_Impl`、`CF123A_ShortName_MIL`、`CF123A_ShortName_SIL`。
- 传统 Git 工具只能按仓库管理，无法实现组件级批量操作、版本联动、状态聚合等

本工具目标：

- 屏蔽 4000 个底层 Git 仓库，让用户完全以【业务组件】视角做开发管理、版本管理
- 以【业务组件】视角做 CI 管理、基线管理。

### 2. 整体系统架构（高层）

- 前端
  - 纯网页级动画、卡片、状态看板、无需任何 QT 呆板界面。
- 后端
  - 多独立常驻后台进程、隔离职责、高并发、不卡 UI。
- 本地结构化数据库
  - 存储远程 Git 元数据、本地状态、对比结果等。
- 组件双数据源驱动
  - 远程：Gitea 组织 API + CI 流水线 API
  - 本地：本机真实 Git 仓库文件状态

### 3. 四大核心高阶能力

> 归档注：原文标题为“四大”，实际仅列出 3 项（能力 1/2/3），此处原样保留。

#### 能力1：组件级Git聚合管理（核心基石）

- 自动识别组件四仓绑定关系（统一前缀+固定四类后缀）
- 支持组件级批量操作：批量 Clone、批量 Checkout、批量切换 Tag、批量 Pull、批量删除
- 支持单仓库独立 Commit/Push，不强制四仓统一提交

#### 能力2：全自动组件版本状态感知（无需人工沟通）

自动计算每个组件整体状态：

- 本地版本落后远程
- 本地版本超前远程（本人开发中）
- 远程本地分叉（存在冲突需 Merge/Rebase）
- 本地缺失组件仓库

全程自动探测、自动刷新、可视化展示。

#### 能力3：CI流水线状态联动

自动绑定每一次 Commit 对应的 CI 结果：

- CI Building（进行中）
- CI Pass（通过）
- CI Fail（失败）

无需查看邮件，客户端实时预警。

### 4. 高层业务规则（不可改动）

- 组件定义永久固定：1 组件 = Design + Impl + MIL + SIL 四仓
- Git 组织仓库命名全局唯一，无需程序校验前缀合法性
- 所有自动化判断以「远程 Git 真实数据 + 本地真实 Git 数据」双为准
- 工具操作 + 开发者手动 Git 操作 全部可被系统兜底识别

### 5. 高层非功能需求

- UI 必须网页级炫酷动效、卡片化、状态色标化
- UI 全程丝滑，所有耗时操作后台进程执行，不阻塞前端
- 支持上千仓库元数据管理、百级本地组件实时监控
- 状态刷新秒级感知

## 二、LLR 低阶详细需求文档（Low-Level Requirements）

（超细颗粒度、进程拆分、数据表结构、逻辑规则、前端交互全覆盖）

### 第一部分：后端架构设计（多独立单职责常驻进程）

所有进程完全解耦、独立运行、互不阻塞、异常自恢复

#### 进程1：远程Git全量元数据同步进程（低频全量同步）

**职责**

- 唯一负责：拉取 Git 组织下 所有 4000+ 仓库 的全局元数据
- 不读取本地文件、不做对比、不操作本地 Git

**同步内容**

- 所有仓库名称、归属组件前缀
- 所有分支列表
- 所有 Tag 列表 & Tag 对应 CommitHash
- 所有分支最新 CommitHash
- 仓库创建/更新时间

**执行策略**

- 执行间隔：6 小时一次全量同步
- 超时机制：单次同步 120s 超时
- 失败策略：自动重试 2 次，失败写入日志，不影响其他进程
- 增量优化：仅更新变更仓库，不重复写入未变动仓库

**落地输出**

写入数据表：`git_remote_meta`

#### 进程2：本地组件增量状态轮询进程（高频监控）

**职责**

- 唯一负责：只监控本机已克隆的组件（100+ 量级，一般不会有人下载全量下载 4000 个仓库到本地）
- 读取本地真实 Git 仓库状态 + 调取 CI API

**采集内容**

- 本地当前分支
- 本地当前最新 CommitHash
- 本地所有未推送 Commit 列表
- 当前 Commit 对应 CI 流水线状态（Pending / Pass / Fail）

**执行策略**

- 执行间隔：30 秒/次
- 只遍历本机存在的组件目录
- 不访问远程全部仓库，性能极高

**落地输出**

写入数据表：`git_local_cache`

#### 进程3：远近版本智能对比计算进程（核心算法进程）

**职责**

- 唯一负责：状态计算、差异判定、冲突判定
- 读取：远程元数据表 + 本地缓存表
- 输出五大标准状态（组件单仓级别）
  - 本地正常同步（完全一致）
  - 本地落后远程（需要 Pull 更新）
  - 本地超前远程（本人正在开发未推送）
  - 远程本地分叉冲突（双方并行开发，需 Merge/Rebase）
  - 本地仓库缺失（本机无该组件对应阶段仓库）
- 组件整体聚合规则
  - 一个组件整体状态 = 四仓状态合并展示
  - 只要任一仓库异常，组件整体标异常高亮

**执行策略**

- 执行间隔：10 秒/次
- 纯内存比对，无 IO 阻塞

**落地输出**

写入数据表：`component_status`

### 第二部分：数据库表结构设计（极简五表架构）

> 归档注：原文标题为“五表”，实际仅定义表 1/2/3 共 3 张。

#### 表1：git_remote_meta（远程全局仓库元数据表）

- `component_prefix`：组件前缀
- `repo_type`：仓库类型（design/impl/mil/sil）
- `latest_commit`：远程最新 CommitHash
- `branch_list`：所有分支
- `tag_list`：所有版本 Tag
- `update_time`：远程更新时间

#### 表2：git_local_cache（本地真实状态缓存表）

- `local_commit`：本地最新 Commit
- `local_branch`：本地当前分支
- `unpush_commit_count`：本地未推送提交数
- `ci_status`：当前 CI 状态
- `scan_time`：扫描时间

#### 表3：component_status（组件最终状态表）

- `repo_status`：五大状态枚举
- `is_error`：是否异常
- `error_msg`：异常说明
- `component_full_status`：组件整体汇总状态

### 第三部分：前端WebView2详细低阶需求

#### 页面1：组件总览看板页

**视觉风格**

- 网页级炫酷卡片、渐变、动效、hover 高亮、状态色标

**卡片状态色标体系**

- 绿色：完全同步正常
- 黄色：本地落后需更新
- 蓝色：本地超前（自主开发中）
- 橙色：分叉冲突待处理
- 红色：CI 失败 / 仓库缺失异常

**组件操作功能（组件级批量）**

- 输入组件前缀 → 一键批量 Clone 四仓
- 输入 Tag 版本 → 四仓批量切换 Tag
- 组件批量 Pull、批量 Checkout
- 组件一键整体删除（本地四仓全部清空）

**单仓精细操作**

- 支持对四仓任意单仓：Commit / Push / Pull / Reset

### 第四部分：兜底容错低阶规则（重要）

- 开发者手动使用外部 Git 工具提交代码 → 进程2 轮询自动感知，完全兜底，不依赖本工具操作
- 远程他人更新版本、打 Tag、合代码 → 进程1 全局同步自动抓取
- 任意进程崩溃自动重启，不影响 UI
- 所有状态变更留痕日志，可回溯排查

### 第五部分：技术栈

- 后端：C# .NET 常驻多进程架构
- 前端：未定
- 本地数据库：高性能嵌入式数据库（替代笨重 Postgres、优于 SQLite）
