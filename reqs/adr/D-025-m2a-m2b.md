## 1. 背景（为什么必须做这个决策）

### 1.1 原 M2 出口把“单仓安全交付”和“批量/作业/审计”捆成了一个不可达里程碑

SRS v0.3 §3.3 的 M2 出口（v0.3.1 修订前）要求一次交付以下全部内容：

- 批量 Clone/Pull/Checkout/Tag/SYNC/Delete/Restore/Create；
- 底部单仓按钮条 PULL/FETCH/CHKOUT/COMMIT/PUSH 接入（前置/确认/失败/进行中/审计）；
- 任务中心、备份 ref、审计日志、写前 journal；
- 写操作 AC（`AC-OP-01…35`、`AC-REPO-01…11`、`AC-SAFE-01…04`）+ `AC-UI-08/10/11` 全绿；
- 故障注入通过、状态×按钮矩阵 14 主状态全覆盖。

`docs/archive/review-m2-req.md` §5 的逐项核对结论是：**16 个出口核对项中 1 项通过、4 项部分、11 项未满足**。也就是说，该 M2 出口在可预见的时间内不可达，继续按该口径推进只会产生“口头完成、无法验收”的状态。

### 1.2 当前实现证明的是“单仓五键的真实 git 语义”，不是“M2 出口”

`docs/archive/m2-ops-status.md` 记录：FETCH/PULL(`--ff-only`)/CHKOUT/COMMIT(staged-only)/PUSH 已在真实 Gitea 上验证，234/234 单测（Core 71 + Host 163），`staged-only` 危险行为已修。这说明**单仓五键的可执行主链路是成立的**，也是唯一可以诚实拿出来复评的子集。

但三路对抗评审均判 Gate 不通过：

| 评审 | 关键结论 | 与本 ADR 的关系 |
|---|---|---|
| `docs/archive/review-m2-code.md` | P0-1：PAT 注入前不绑定 origin/pushurl，配置非法时 fail-open，PAT 可发往任意 URL（已用本机 HTTP 抓包证明）；P1-1：CHKOUT/PULL 静默覆盖 ignored 文件；P1-2：门禁基于永不失效快照（TOCTOU）；P1-3：CHKOUT ref 不存在时“假成功” | 这 4 项全部纳入 **M2a 安全四件**，**不得**因为“只交付单仓子集”而降级 |
| `docs/archive/review-m2-req.md` | FR-ACT 7 条：1 通过、2 部分、4 不通过；无确认条且 PUSH 零确认；tooltip 无错误码；矩阵双源；无 read-through/CAS/BUSY/取消/审计 | 确认条、tooltip、矩阵单源、CAS/BUSY、审计一条 → M2a；取消/job/任务中心 → M2b |
| `docs/archive/review-m2-ux-fixcheck.md` | 新 P0：PUSH 零确认直接写远端（且 `Alt+5` 同样无确认）；P0-5 焦点未闭环（ComponentDrawer ESC 后焦点落 BODY） | 一律不得以“M2b 以后再说”降级：确认条与焦点属 **M2a 出口** |

### 1.3 需求治理缺口（RQ-06）

`docs/archive/review-m2-req.md` RQ-06 指出：SRS v0.3 §3.3 未授权 M2a/M2b 拆分，因此即使实现方只做了单仓五键，也无法给出可审计的放行结论。本 ADR 即为该变更授权的正式记录；SRS v0.3.1 同步拆分里程碑、回写 AC 与追溯矩阵。

## 2. 决策

### 2.1 总决策

1. **M2 拆分为两个顺序里程碑：M2a（单仓安全交付）→ M2b（批量/作业/审计）**。
2. **M2 整体出口 = M2a 出口 ∧ M2b 出口**；任何一个子里程碑通过都不等于“M2 交付完成”。
3. **M2a 不是“降低要求的 M2”**：M2a 把评审指出的全部 P0 安全/交互项纳入自身出口；M2b 补的是能力面（批量、作业、备份、审计完整表、写前 journal），不是把安全项挪后。
4. **当前状态 = M2a 待复评**。在 M2a 出口 AC 全绿并产出验收报告前，不得对外写“M2 已通过/已交付”，`m2-ops` tag 保持撤销。

### 2.2 M2a 范围（单仓安全交付，必须先完成）

M2a **必须全部交付**以下内容，缺一项即 M2a 不通过：

| # | 能力 | 条款锚点 | 验收 AC |
|---|---|---|---|
| 1 | 单仓五键 `PULL`/`FETCH`/`CHKOUT`/`COMMIT`/`PUSH` 在真实 Host 上可用：PULL 仅 `--ff-only`；COMMIT 仅提交 staged（不做 `add -A`）、message 1–200；PUSH 禁 force、要求 upstream（NO_UPSTREAM 走“发布分支并建 upstream”确认；EMPTY 首推归 M2b，M2a 构建按空仓无提交禁用）；CHKOUT 选择器来自 `remote_ref`（分支/Tag + 搜索 + dirty 时 `stash -u` 选项）；参数一律 `ArgumentList` | FR-REPO-01/02/03、FR-ACT-03、§7.6 | AC-UI-10、AC-UI-10b、AC-SAFE-17 |
| 2 | **安全四件（评审 P0/P1 原样纳入，不降级）**：<br>① 凭据作用域：注入 PAT 前锁内校验 `git remote get-url origin` **与** `--push` 均与 Gitea base（scheme/host/org）一致，配置不完整/非法时 **fail-closed**；header 用 `http.<base>.extraHeader` URL 作用域；不匹配返回 `E_CREDENTIAL_SCOPE` 且不启动 git 网络进程；<br>② 写前 read-through 重扫 + CAS（preflight HEAD == 执行时 HEAD），失败 `E_CONCURRENT_CHANGE`、零改动；<br>③ ignored 文件不被静默覆盖：CHKOUT 用 `--no-overwrite-ignore`，PULL 改 `fetch` + `merge --ff-only --no-overwrite-ignore`；<br>④ ref 校验：CHKOUT ref 必须 `rev-parse --verify` 存在（禁止“假成功”）；分支名拒绝前导 `-`/`+`；PULL 显式分支必须等于当前分支；detached 禁止 PUSH | FR-ACT-03、FR-ACT-05、FR-SAFE-03/06、§7.5、评审 P0-1/P1-1/P1-2/P1-3 | AC-SAFE-14/15/16/17 |
| 3 | **确认条**：COMMIT/PUSH 在按钮条上方显示 ≤48px 内联确认条（COMMIT：“将提交 N 个文件”；PUSH：“将推送 N 个提交（分支 → upstream）”，NO_UPSTREAM 增“发布分支并建立 upstream”）；未确认时写操作数 = 0；确认条不遮挡/不移动 5 按钮；`Alt+5` 与按钮同路径，**不得零确认写**；破坏性覆盖不进按钮条 | FR-ACT-04、AC-UI-10 | AC-UI-10a/10b |
| 4 | **焦点闭环**：确认条/对话框初始焦点在条内、焦点陷阱、ESC 关闭后焦点归还触发控件；ComponentDrawer（组件详情抽屉）ESC 后焦点归还触发控件；键盘可完成确认/取消 | FR-WS-04、FR-ACT-04 | AC-UI-13（M2a 复验） |
| 5 | **tooltip 三段式 + 矩阵单源**：Host `GetAvailability` 为 14 态×5 键唯一权威（含 `RequiresConfirm`、`ReasonCode`）；UI 删除第二套矩阵、只消费 Host 返回；禁用 tooltip **冻结格式 `原因 [E_*] → 替代动作`**（v0.3.1-r2 修订：三段仍为“原因/错误码/替代动作”，但改紧凑内联写法，**替代旧的冒号三段式 `原因：…；替代：…；错误码：…`**，避免 85 个按钮 title 过长）；错误码命名以 Host `E_*` 为准并在 `details.srsCode` 给出附录 D 映射（`E_REPO_BUSY`↔`OP-E001`、`E_CONCURRENT_CHANGE`↔`OP-E002`、`E_ACTION_NOT_ALLOWED`/`E_CREDENTIAL_SCOPE`↔`OP-E004` 族） | FR-ACT-02、§7.6 末条、评审 RQ-05/RQ-07、P0-02/P0-11 | AC-UI-08（含矩阵夹具单源） |
| 6 | **操作审计一条（audit-lite）**：每次单仓动作落 1 行 `operation_log`，至少含 `ts/actor/componentId/repoType/action/before_head/after_head/result/error_code/request_id`；成功与失败都写；同一操作不得写 0 行或多行；重启后可查 | FR-ACT-06、FR-OP-09 的 M2a 子集 | AC-OP-33 |
| 7 | **真实数据**：验收须在真实 Host + 真实 Gitea（或 `gitea.exe` 单二进制夹具）上执行五键动作；Mock 只允许用于注入 14 状态/错误态，**不得**用 Mock 动作回执替代真实写入证据 | 评审 RQ-07、§7.5 | 验收报告 `docs/archive/m2a-ac-report.md` 证据清单 |
| 8 | **M2b 边界提示**：批量（Clone/Pull/Checkout/Tag/SYNC/Delete/Create）与任务中心入口在 M2a 构建中明示“**M2b 未接入（批量/作业/审计）**”；点击不产生任何 Host 写调用，也不得静默无响应 | 本 ADR §2.4、FR-ACT-07 | AC-UI-15 |
| 9 | 保留现有硬约束：staged-only、`--ff-only`、PUSH 无 force、token 不进 argv/日志/响应、per-repo 串行、输出脱敏 | FR-REPO-01/03、FR-SAFE-03/06 | AC-UI-10、AC-SAFE-14 |

**M2a 明确不含（归 M2b）**：

- 批量写：Clone/Pull/Checkout/Tag/SYNC/Delete/Restore/Create，SYNC 强覆盖 + `refs/backup/*`、`.trash` 软删除与恢复；
- 作业：`job`/`job_item`/`JOB_UPDATED` 事件、`jobId` 返回、任务中心、合作式取消、仅重试失败项、job 持久化与重启不重复执行；
- 审计完整面：`operation_log` 查询/导出/90 天保留、逐仓/批量审计、与 job 关联；
- 写前 journal + 崩溃 reconcile（FR-SAFE-04）；
- FR-REPO-05 其余修复类：Repair/Re-clone、detached HEAD 建分支、EMPTY 首推建 upstream（NO_UPSTREAM 的 set-upstream 发布分支确认已含在 M2a，属唯一例外，理由见 §2.5-④）；
- 离线降级/离线 FETCH 禁用（FR-ACT-03 的离线子项）、状态栏队列 6 段完整实现等 P1 项（见 §2.6 债务表）。

> **诚实标注**：M2a 出口**不主张** FR-ACT-05/06 全量通过。M2a 的 FR-ACT-05 子集 = spinner/同仓串行/状态栏进行中/错误码+中文/BUSY/CAS/失败可读 + 重新预检后再次触发；合作式取消与 job/jobId 属 M2b；M2a 的 FR-ACT-06 子集 = ≤2s 回写 + 状态栏模板 + 审计一条；任务中心“仅重试失败项”属 M2b。任何 M2a 报告都必须按此口径写，不得写成“FR-ACT 全通过”。

### 2.3 M2b 范围（批量/作业/审计）

M2b **必须全部交付**：

1. 批量 Clone/Pull/Checkout/Tag/SYNC/Delete/Restore/Create（FR-OP-01…12），含受控 SYNC 的备份 ref、dry-run、二次确认；
2. job 作业模型：`job`/`job_item`、`JOB_UPDATED` 事件、`jobId`、任务中心（队列/进行中/历史/逐仓结果）、合作式取消、**仅重试失败项**、job 持久化且重启不重复执行；
3. 备份/回滚：`refs/backup/*`（≥30 天，`backup.retentionDays`）、`.trash`（30 天）、Restore 入口与冲突预览；
4. 审计完整表：`operation_log` 全字段/查询/导出/≥90 天保留、批量与 job 关联；
5. 写前 journal + 崩溃 reconcile（FR-SAFE-04）；
6. FR-REPO-05 其余修复类（Repair/Re-clone、detached 建分支、EMPTY 首推建 upstream）；
7. 离线降级与 FR-ACT-03 离线子项、状态栏 6 段完整口径（作为 M2b 收口项）。

M2b 出口 AC：`AC-OP-01…AC-OP-35`（D-028 增补 34/35）、`AC-REPO-01…AC-REPO-11`、`AC-SAFE-01…AC-SAFE-13`、**AC-UI-10c**、**AC-UI-16**、故障注入报告、14 态矩阵在 M2b 构建下复验。M2b 依赖 M2a 出口先通过（矩阵单源、审计链路、错误码体系是 M2b 的前置）。

### 2.4 边界硬约束（防止用“拆分”做宽松解释）

1. **M2a 不得包含“可点但无效果”**：任何按钮/入口点击后必须出现可感知结果（执行、确认条、明确错误码/禁用原因或“M2b 未接入”提示）；无 Host 调用且无 UI 反馈 = 缺陷（AC-UI-09/15）。
2. **M2a 不得包含“零确认写”**：COMMIT/PUSH 必须经确认条确认后才调用 Host；`Alt+5`、菜单、任何脚本路径同规则。**PUSH 确认条口径以 SRS FR-ACT-04 为准，不采用 `docs/archive/ui-redesign-spec.md` §6.4 的“常规 PUSH 免确认”**（RQ-02 裁决；见 §2.5-②）。
3. **M2b 未完成不阻塞 M2a 复评**，但：①M2a 报告与 UI 必须保持“M2b 未接入”明确提示（AC-UI-15）；②M2a 不得因此移除任何安全项；③M2a 通过后不得对外宣称“M2 完成”，只能写“M2a 已通过、M2b 未接入”。
4. **不得以 Mock/单测数量替代 AC 证据**：234/234 单测不构成任何 AC 通过；`docs/archive/m2-ops-status.md` 的 Gate 状态在复评前保持“不通过”。
5. **不得删除或弱化**已冻结条款：§7.5 read-through+CAS、§10.3 凭据 header-only、FR-SAFE-03/06、附录 D 错误码；如需变更必须另立 ADR。

### 2.5 口径裁决（冻结 AC-UI-08 的可判定性）

| # | 争点 | 裁决 | 理由 |
|---|---|---|---|
| ① | §7.6 `DIVERGED` 的 Pull(ff) 写“⚠ 仅展示不自动 merge”（RQ-01） | **按禁用实现与验收**：单元格改为 ❌，tooltip 给替代动作“先手动 merge/rebase 后重扫”。M2b 的“受控 SYNC”不改变本裁决 | ⚠ 图例=“允许但需 dry-run/备份/确认”，与“不自动 merge”自相矛盾；禁用是更严格语义，Host/UI/spec §6.2 已一致 |
| ② | COMMIT/PUSH 是否确认（RQ-02；SRS vs `docs/archive/ui-redesign-spec.md` §6.3/6.4） | **以 SRS FR-ACT-04 为准：COMMIT/PUSH 一律确认条**；spec §6.4“常规 PUSH 免确认”作废，M2a 实施与 AC-UI-10a/10b 按此验收 | 安全要求不得为“通过”而降级；PUSH 是写远端不可逆操作，零确认是本轮新 P0（`docs/archive/review-m2-ux-fixcheck.md` NP0-1） |
| ③ | 矩阵中 `—`（无需执行）如何断言（RQ-01 同族） | `MISSING` 的 Fetch/Pull、`EMPTY` 的 Pull 按 **disabled** 编码断言（AC-UI-08 以 `disabled=true` 判定） | “无需执行”在按钮语义上等价于不可点；冻结后 AC 可自动断言，不再逐次解释 |
| ④ | NO_UPSTREAM / EMPTY 的 PUSH（RQ-03） | `NO_UPSTREAM`：允许 PUSH，但必须走确认条“发布分支：将推送并建立 upstream”（`setUpstream=true`）——**这是 FR-REPO-05 唯一纳入 M2a 的子项**；`EMPTY`：M2a 构建按“空仓无提交”禁用并 tooltip 指向 M2b 首推（E7 已证明 unborn HEAD 直接 push 必失败），M2b 构建由 FR-REPO-05 恢复矩阵 | 既满足 §7.6 发布分支语义，又避免零确认写；EMPTY 首推需要“有提交”的前置，属 M2b 修复类能力，不能在 M2a 假启用 |
| ⑤ | `USYNCED` 的 CHKOUT 确认标志漂移（UI c vs Host/SRS Y） | **以 §7.6 矩阵为准（免确认，Y）**；UI 第二套矩阵删除，确认标志只由 Host `RequiresConfirm` 输出 | §7.6 末条禁止另写一套判断；UI 漂移属实现缺陷，AC-UI-08 断言 |
| ⑥ | tooltip 错误码命名（RQ-05） | UI 展示 Host `E_*` 码（`E_REPO_BUSY`/`E_CONCURRENT_CHANGE`/`E_CREDENTIAL_SCOPE`/`E_REF_NOT_FOUND`/`E_INVALID_ARGUMENT`/`E_ACTION_NOT_ALLOWED`），Host `details.srsCode` 给出附录 D 映射（OP-E001/OP-E002/OP-E004 等）；新增 `E_CREDENTIAL_SCOPE`、`E_REF_NOT_FOUND` 需在实现时补入 `BridgeErrors` 与附录 D 映射表 | 冻结断言字符串，避免“有错误码但各写一套” |

### 2.6 已知债务（显式记录，不隐藏、不冒充已完成）

| 债务 | 归属 | 说明 |
|---|---|---|

## 3. M2a 出口 AC（可自动验收）

M2a 出口 = 下列 13 条 AC 全绿，且每条都有可复跑证据（CDP/Host 测试/fixture），产出 `docs/archive/m2a-ac-report.md`：
