# I18N 可行性评估（后续需求输入）

> 状态：**仅评估，未实现**；不属于 M2b。作为后续 `FR-I18N` 需求/ADR 的输入。
> 结论：可行，建议 M3 前置独立立项；不能与 M2b 功能收尾混做。

## 1. 现状盘点

| 层 | 现状 | 问题 |
|---|---|---|
| Vue 组件 | 模板/提示/toast/tooltip 大量硬编码中文 | 需抽 key，约数百条 |
| Store/viewmodel | 中文状态文案、动作名、错误码解释 | 需 locale store + 消息目录 |
| Host 错误 | `E_*` + 中文 message | 国际化应基于 `errorCode + 参数`，UI 本地化；不能只翻译前端 |
| 自检/CDP | 断言中文文案（“离线/远程不可达”“已导出…”） | 改为 `data-testid`/错误码，避免语言耦合 |
| 布局 | 紧凑工具栏/表格/确认条（≤48px） | 英文更长，需断点/密度/截断策略；用户也要求“UI 不需要那么密集” |
| 术语 | 组件/仓/四仓/基线/Tag/SYNC 混用 | 需中英术语表，中文文案也应按术语表重写 |

## 2. 建议改造

1. 引入 `vue-i18n`，`locales/zh-CN.ts`、`locales/en-US.ts`；key 命名 `area.component.element`。
2. Host 错误返回稳定 `code + details`，前端 `errorMessage(code, params)`；日志/审计保持 code。
3. 抽取消息目录前先做“文案清单”脚本（扫描 `.vue/.ts` 中文字符串，输出待迁移清单）。
4. 自检脚本改为断言 testid/属性（本轮 M2b 已部分这样）；文案相关断言移入 i18n 专项自检。
5. 布局：增加密度模式（紧凑/舒适）；英文长文本用 min-width/ellipsis/wrap；确认条高度断言需按 locale 复验。
6. 中文文案二次审校：术语统一、去口语化、错误提示三段式（原因/影响/动作）。

## 3. 验收建议（FR-I18N 草案）

- 中英切换即时生效，无需重启；默认跟随系统，可手动覆盖。
- 全部用户可见文案来自消息目录（扫描器无硬编码中文，例外白名单）。
- 错误码在两种语言下都有可读 message；审计/日志仍为稳定 code。
- 布局：中/英下无溢出、无遮挡；确认条 ≤48px 或按新密集度重新验收。
- CDP 自检在中英两 locale 下均通过；不依赖中文文案断言。

## 4. 成本/风险

- 成本：UI 全模板 + store + 文案清单 + 错误映射 + 自检迁移，属跨模块需求；建议单独里程碑。
- 风险：Host/UI 双源文案、长英文挤压紧凑布局、自检大面积改断言。
- 前置：先完成 M2b 功能收尾与 M2b final Gate，避免同一批文件反复冲突。
