- **问题**：合并声明“唯一需求源”，但正文仍把冻结与验收权威交给一个已删除的外部文件；§13.1.1 的 14 条 AC-UI 与 §13.1.2 的 9 条“未回写”永远不可能回写。结果：**“冻结的 AC 集合”到底是哪些、冲突时谁优先，无法唯一确定**；Annex A §5.1 冻结清单（162 条）与 §3.3 M0 出口“含 AC-UI-01…14”（L144）互相不覆盖；AC 编号规则（11 域、禁止子字母）与 AC-UI 冲突。
- **最小修改建议**：①删除“权威 AC 目录 = 外部文件/回写”的整段表述，改为“Annex A 即唯一 AC 目录”；②把 AC-UI-01…14、AC-UI-10a/b/c/15、AC-SAFE-14…17、AC-OP-33 正式并入 Annex A（新增 `UI` 域并修订 §1.2 域清单/子字母规则；或明确“§13.1.1/§13.1.2 为 Annex A 的正文组成部分”）；③统一更新规模统计、§5.1 冻结集、§3.3 M0/M2a 出口、§5.3 检查项、§5.4 冻结记录为合并后口径。

### P0-3 `baseline_snapshot` 数据语义与 AC-OP-12/AC-OP-13、§8.1 主键互斥
- **位置/证据**：AC-OP-12 ③（L2287）“baseline_snapshot 写 4 行，SIL 行 `tag_present=0`、`commit_sha` 为空/NULL”；AC-OP-13 ④（L2295）“记录新 commit 且**不丢历史行**（旧行保留或按快照语义新增）”；§8.1 `baseline_snapshot` PK `(component_id, tag, repo_type)`（L408，字段名 v0.2 起冻结，L389）；§14.4（L3168–L3174）“每个仓写入…”“缺 Tag 仓写 0 或按设计不写行，须在实现评审定稿”“baseline 仅在 TAG job 成功项写入，失败/跳过不写”。

- **最小修改建议**：冻结一套唯一口径并回写 AC 与 §8.1：建议“**每次 TAG job 固定写 4 行**：命中仓 `tag_present=1` + `commit_sha` + `tag_object_sha`（轻量 tag 为 NULL），缺 Tag 仓 `tag_present=0`、`commit_sha=NULL`”；“tag 移动/重打 **覆盖同键行**并在 `operation_log` 留历史（或把 `captured_at`/`snapshot_id` 纳入主键，需 ADR）”；删除“实现评审定稿”句并在 §14.4 引用 AC 编号。

### P1-4 Repair/Re-clone 的“失败零改动/回滚”不可实现且不可测
- **证据**：§14.3（L3158–L3162）“REPAIR：`git init`、设置 origin、fetch、按远端默认分支安全检出；**不覆盖已有文件，冲突则失败零改动**”“RECLONE：先将原目录移动到 `.trash/<stamp>/<repoName>`，再 clone；**移动失败则不 clone**”“失败时仓库零改动”；AC-OP-05 ③“原有目录内文件 hash 前后不变”（L2231）；AC-REPO-08（L2508–L2514）仅成功路径。
