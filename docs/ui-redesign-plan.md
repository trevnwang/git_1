# UI 重构开发节奏与阶段计划（自主迭代）

> 基准：用户提供的 `docs/images/reference/main-ui-reference.png`（唯一视觉基准；与旧 SRS 冲突时以图为准）。
> 模式：每个阶段 = 实现 → 多智能体对抗评审（需求 / 代码 / UI）→ 修复 → 回归 → 提交；阶段间不等待用户。

## 阶段划分

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| S1 设计基线 | 参考图解读、UI 规格、SRS delta（工作台/文件夹视图/FR/AC）、代码差距与 API 方案 | 三份文档评审通过；10 个 CI 锚点新落点明确；无未裁决冲突 |
| S2 Host 数据层 | 文件树 / 工作区树 / 组件详情 / 打开文件 API；路径安全；缓存与懒加载；单测 | 单测全绿；路径逃逸/深目录/中文路径/大目录测试通过；无 UI 改动 |
| S3 前端新工作台 | 菜单栏/标题区/组件卡片/四仓文件树/右侧信息/底部按钮/状态栏 + 文件夹视图；Mock 驱动 | 1440/1280 无溢出；CDP 锚点 10/10；树展开/选中/视图切换可用 |
| S4 真实数据联调 | 接 Snapshot + 文件树 + 工作区树 + 打开文件；真实 Gitea/本地夹具 | 真实 RTCRepos 数据渲染；双击打开文件；刷新；0 console error |
| S5 对抗评审与修复 | 3 路评审（需求符合度 / 代码质量与安全 / UI 视觉与交互）+ 修复 | P0/P1 清零；截图对比参考图；AC 更新 |
| S6 单仓操作 | PULL/FETCH/CHKOUT/COMMIT/PUSH 的可用性与安全（只读→写操作边界、确认、失败态） | 操作前置校验/失败提示/日志；不误伤；评审通过 |
| S7 收口 | 全量回归、性能、打包、文档、打 tag | `m1-baseline` / `ui-v3` tag；验收报告 |

## 对抗评审机制（每阶段结束）

- **需求评审**：对照 SRS v0.3 与参考图，检查 FR/AC 是否覆盖新 UI、文件夹视图、操作按钮、CI 预留；找“写了没落点/落点无验收”。
- **代码评审**：Host API 边界（路径安全、超时、并发、异常）、前端状态/性能/可访问性、契约兼容；阻挡合并的问题必须修。
- **UI/交互评审**：与参考图逐区域对比（比例、层级、信息密度、颜色、双击/展开/选中/禁用态）；CDP 截图 + 真实鼠标键盘验证。
- 评审产出必须含：结论（可继续/需修复）、P0/P1 清单、证据位置；修复后复评一次。

## 视觉基线（来自参考图）

- 菜单栏 → 标题区（产品名/版本/组件数）→ 主工作区（左：组件卡片列表；中：2×2 四仓文件树；右：选中仓信息/构建状态）→ 底部按钮栏（PULL/FETCH/CHKOUT/COMMIT/PUSH）→ 状态栏。
- 面板比例参考：左 ≈ 20%，中 ≈ 62%，右 ≈ 18%；整体 1440×900 基线，1280×800 最小。
- 状态色沿用 SRS §11.2 token；CI 仍是独立通道。
- 新增“文件夹视图”：工作区根目录树（组件目录/仓库目录/文件），与工作台视图一键切换。

## 自测方式

- 所有交互用 CDP `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` 真实驱动（不用 JS click）；
- 每个阶段至少截图 3 张（工作台/文件夹视图/操作态），归档 `docs/images/ui-v3/`；
- 真实环境：RTCRepos 15 仓 + 本地工作区 `artifacts/real-test/workspace`；本地 mock 作为无 Host 回退。

## 约束

- 不回退已冻结的安全规则：路径必须在工作区根内、写操作需确认/备份（M2）、token 不入日志；
- 旧看板可保留为“表格视图”备选，但默认主界面按参考图；
- 每阶段结束提交（`feat(ui): ...` / `fix(ui): ...`），S5 后打 `ui-v3` tag，S7 后打 `m1-baseline`。
